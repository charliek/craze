# 08 — Decisions

Append-only. A reversal is a new row naming the one it replaces. IDs are
`TD-nn`, distinct from `D-nn` (native harness) and `SD-nn` (session control).

| ID | Date | Decision | Why | By |
|---|---|---|---|---|
| TD-01 | 2026-10-10 | The Claude Code plugin ships inside the craze repo: a repo-root `.claude-plugin/` with `plugin.json` and `marketplace.json` (source `./`), plus `agents/` and `skills/craze/`, versioned with the release. It is not published from `cc-plugins`. | The way shed and prox ship theirs. The plugin moves with the commands it drives, and one release bumps both. | owner |
| TD-02 | 2026-10-10 | A sub-agent is a thin Claude Code agent (`model: haiku`, `effort: high`, `tools: Bash`) that forwards the task to craze and returns the result verbatim. | It gets Claude Code's agent identity: background runs, notifications, `SendMessage`, `TaskStop`. The orchestrator sees only the final message. Measured at about $0.0014 and 5–6 s per call ([02](02-experiments.md) E3, E4). `model` must be set or the wrapper runs on the parent's model. | owner (Haiku 5.5, high effort); evidence E3–E4 |
| TD-03 | 2026-10-10 | No LLM gateway route, meaning Claude Code's own harness driving a non-Claude model through craze. | Claude Code's documentation says routing to non-Claude models through a gateway is unsupported, and every Opus request would pass through craze. | evidence |
| TD-04 | 2026-10-10 | The new commands are not exposed in the TUI. Their sessions are ordinary sessions; the TUI changes only how they are labelled and how `craze -c` picks a session. | They are for scripts and agents. Seeing the sessions in the session list, and attaching to them, is useful as it is. | owner |
| TD-05 | 2026-10-10 | A sub-agent is a hub session (`session.create`, in its own detached host), not a `craze prompt` run. `craze prompt` stays as it is: in process and hermetic. | The session outlives each call: follow-ups keep their context, `craze attach` watches live, and a turn longer than one Bash call keeps running ([02](02-experiments.md) E2–E3). `craze prompt`'s in-process path is what the tests, the V2 parity check and `eval/` rely on. | evidence |
| TD-06 | 2026-10-10 | The client is Go, inside the `craze` binary, built on the existing hub and protocol clients. It is not a script shipped with the plugin. | `craze` is already on PATH, so there is no script to locate (`cc-plugins` resorts to `find` over plugin caches) and no Python dependency. It reuses the reconnect and command-retry logic `craze attach` already has. | evidence |
| TD-07 | 2026-10-10 | An MCP server is deferred, not rejected. | Its calls background themselves after two minutes and need no wrapper, but it loses the sub-agent identity (`SendMessage`, the agent list). Worth revisiting if the wrapper's overhead or Bash's constraints bite ([10](10-follow-ups.md)). | evidence |
| TD-08 | 2026-10-10 | An unattended session's host is spawned directly by the waiting command, through the CLI's own spawn path (the TUI launcher's), not through the hub's `session.create`. `session.create` gains nothing in T1. Narrows TD-05's mechanism; TD-05's choice of a detached host over `craze prompt` stands. | An older hub stays alive while any host lives, so gating on new hub capabilities would block every delegation after an upgrade. Direct spawn needs no protocol, schema or fixture change, and keeps clear of plan 040's protocol work. Plan 041's panel (CodeRabbit). | panel, adopted |
| TD-09 | 2026-10-10 | An unattended host runs `Interactive: false`, with `craze prompt`'s explicit approval policy. | Native background children and bash jobs exist only on interactive sessions; their results arrive in a later wake turn, after a waiter would already have reported the interim message. `Interactive` controls only that and the ask defaults, which the explicit policy overrides. Plan 041's panel (CodeRabbit). | panel, adopted |
