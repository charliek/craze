# 10 — Open questions

Each has a default so a plan can proceed without an answer. Resolved rows are
kept and rewritten in place as `**Resolved (SD-nn).**`.

| # | question | default if unanswered | needed by |
|---|---|---|---|
| SQ1 | Journal location and naming. | Own tree for every provider, `$CRAZE_HOME/journal/<cwd-slug>/<utc>_<incarnation-id>.jsonl`, same slug and timestamp scheme as the harness store so files pair by eye. The slug helper is reimplemented or moved, not imported from `internal/harness/store`. | S1a |
| SQ2 | **Resolved (SD-18).** **Answered:** deltas are not coalesced in the log; every emitted event is one sequenced line, and live and replay share that representation. Folding belongs to the transcript model (S1c). | | |
| SQ3 | Journal retention, size caps, and secrets: tool output and prompts can hold credentials. | `0600` files in a `0700` tree, no redaction, `journal = false` opt-out (which also disables the wire sidecar and cannot disable the native model store), no automatic pruning until sizes are measured in real use. | S1a |
| SQ4 | Raw ACP wire capture in a `.wire.jsonl` sidecar: on by default? | **Off in S1a, behind a config key and an env var**, because it needs a tap inside `internal/acp` and its size is unmeasured; revisit the default once S1a's journals have been used. The owner asked for rich debug data, so the tap itself is wanted. | S1a |
| SQ5 | **Resolved (SD-22).** **Answered:** three identities. The durable craze session id, the provider session id, and the host incarnation; cursors and ask ids are scoped to an incarnation. `craze bridge --session` accepts the provider id roost already carries. | | |
| SQ6 | Hub lifecycle: auto-spawned by the first host or client that needs it (prox), or explicit `craze hub`? Does it exit when idle? | Auto-spawn by re-exec, fully detached; exit when the roster is empty and no client is connected, after a registration grace. | S4 |
| SQ7 | Does `craze attach` reuse the full TUI over a socket-backed `agent.Session`, or a thinner viewer? | Full TUI. It is also the best protocol test, and under SQ12's default it becomes the TUI's permanent path. | S2 |
| SQ8 | shed side: who owns SSH re-exec, half-close, and teardown behind the stable local port; how a desktop reaches a session on another machine; how headless sessions with no roost tab get listed on the phone. | The device keeps its pump and only the remote command changes (SD-29); desktop uses the same pump for remote machines and a direct Unix-socket dial locally; headless rows come from a hub roster subscription once S4 exists. | S3 |
| SQ9 | Snapshot and history size for long sessions. | **Bounded from S2**: history is a page with `limit`, `maxBytes`, `beforeSeq`; snapshots have an aggregate byte bound chosen to fit a subscriber's budget (S1c). The first draft's "full snapshot, windowing deferred" was wrong: 5,000 entries at the 64 KiB cap approach 313 MiB. | S1c/S2 |
| SQ10 | Two clients acting at once. | Prompts queue in the engine driver's admission order; settings follow the engine's order and are broadcast with a revision (SD-25); queue edits carry `expectedVersion`; composer drafts are client-local. | S1b |
| SQ11 | Scopes for non-local clients: may a remote client answer `allow_always`, change mode to yolo, or create sessions? | Three scopes (`observe`, `operate`, `approve`); `allow_always` and permission-mode changes need `approve`; local socket clients hold all three. Only matters from S6. | S6 |
| SQ12 | **Quit versus detach, and whether hosts are born detached.** A TUI process is a job of its shell and cannot cleanly turn itself into a daemon in Go; tab close or a login-scope teardown kills it regardless. | **Hosts are born detached from S4 on and the TUI is always a socket client**; what a host does when its last client leaves is policy (default: a plain quit still ends the session, with a confirm when a turn is working; an explicit detach keeps it). Through S3, quit stays quit and the in-process path is the only one. **Decide before the S2 plan**, because it determines whether the socket-backed `Session` is the TUI's permanent path. | before S2 |
| SQ13 | Restoring a transcript from earlier incarnations' journals instead of, or reconciled with, the provider's replay. | Not before S4. Needs rules for which source wins when they differ, for historical asks and interrupted turns becoming terminal records, and for the replay goldens and `--continue`. | S4 or later |
| SQ14 | One attached session per connection, with the hub splicing bytes to the host, versus multiplexing sessions on one connection. | One per connection (`05`): it keeps the hub free of session semantics and lets kernel backpressure reach the host's budget logic. Subscription ids stay so multiplexing is not precluded. | S2 |
| SQ15 | Tool events re-emit full merged state on every update, so a streaming tool grows the log quadratically. Conflate superseded full-state events in queues and the journal, or emit tool deltas? | Measure in S1a's live smoke first (bytes per session, per tool). Conflation is legal because full-state events are convergent; deltas would change the event contract. | after S1a |
| SQ16 | `craze --continue` run twice on one session is legal today and would give two hosts for one durable session. | From S2: the second attaches to the first when its socket answers; otherwise it takes the session's lifetime lock or refuses with the owner's pid. | S2 |
