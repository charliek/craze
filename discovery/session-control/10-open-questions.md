| SQ4 | Raw ACP wire capture in a `.wire.jsonl` sidecar: on by default? | **Off in S1a, behind a config key and an env var**, because it needs a tap inside `internal/acp` and its size is unmeasured; revisit the default once S1a's journals have been used. | SQ5 | **Resolved (SD-22).** **Answered:** three identities. The durable craze session id, the provider session id, and the host incarnation; cursors and ask ids are scoped to an incarnation. `craze bridge --session` accepts the provider id roost already carries. | | |
| SQ6 | **Resolved (SD-37).** **Answered:** auto-spawned on demand by re-exec, fully detached; it exits 60 s after the last live host and the last client are both gone. It learns hosts from the registry and polls them; there is no registration connection. | | |
| SQ7 | **Resolved (Plan 027, S2).** **Answered:** `craze attach` runs the full TUI (`tui.Run`) over `remote.Session`, with `Viewer: true` turning off the pickers, provider persistence, host status reporting and index writes — the host TUI owns those (`internal/cli/attach.go`, plan 027 §3.15). It is the protocol's first full client outside the host TUI and the test harness. | | |
| SQ8 | **Resolved (SD-42, SD-43).** **Answered:** the device keeps its stable local-port pump, re-executing `craze bridge --hub` per accepted connection: one roster connection per machine, one per open transcript. The desktop uses the same exec tunnel for other machines and runs the bridge as a local subprocess for its own. Every craze session, headless or tab-hosted, is listed from the hub's roster; a roost tab craze owns folds into its hub row. Half-close and teardown behaviour is the bridge's (Plan 035; SF-139's residual), and the exact SSH re-exec ownership is S3b's plan to pin, in shed. | | |
| SQ9 | Snapshot and history size for long sessions. | **Resolved (Plan 024, S1c).** The model's own bounds (`transcript.Bounds`): 5,000 entries / 8 MiB retained bytes on the main transcript, 1,000 entries / 1 MiB per child, 32 finished children kept on the roster (plus any still running), 64 KiB per streamed entry. A snapshot has its own byte budget (`SnapshotBytes`, default 4 MiB, a hard cap on the encoded size) filled in order — mandatory sections first (per-item caps, `Truncated`), then the main tail newest-first, then each child the same way — and returns `ErrSnapshotTooLarge` rather than a silent drop if the mandatory sections alone overflow it. Four separate limits are stated and tested: retained model memory, the snapshot's encoded size, the subscription's own storage bound, and decoding peak. Measured on a worst-case session in `12` S1c ("Measurements"). | S1c |
| SQ10 | Two clients acting at once. | Prompts queue in the engine driver's admission order; settings follow the engine's order and are broadcast with a revision (SD-25); queue edits carry `expectedVersion`; composer drafts are client-local. | S1b |
| SQ11 | Scopes for non-local clients: may a remote client answer `allow_always`, change mode to yolo, or create sessions? | Three scopes (`observe`, `operate`, `approve`); `allow_always` and permission-mode changes need `approve`; local socket clients hold all three. Only matters from S6. | S6 |
| SQ12 | **Resolved (SD-33).** **Answered:** quit versus detach, and whether hosts are born detached — session hosts are born detached from S4 on, and the TUI becomes a socket client for good. What a host does when its last client leaves is policy (default: a plain quit still ends the session, with a confirm when a turn is working; an explicit detach keeps it). Through S3, quit stays quit, and the **host's own** default TUI still builds its session in process (`engineBackend`) — S2 already gives it a second, fully remote client instead (`craze attach`, over `remote.Session`), which does not change until S4's headless hosts make every TUI a socket client. **Refined by SD-35 (2026-09-28):** SD-34 moved S4a ahead of S3, so "through S3" now reads "through S2"; from S4a the explicit quit (`/exit`, `ctrl+d`, the second `ctrl+c`) ends the session in every client and closing the terminal leaves it running, and an unattended idle host exits after a configurable timeout. | | |
| SQ13 | **Resolved (SD-39).** **Answered:** the provider's replay stays the resume authority; there is no journal-based restore (SD-23 unchanged). | | |
| SQ14 | **Resolved (Plan 027, S2).** **Answered:** one attached session per connection, no multiplexing. `session.attach` binds one attachment to the connection it was called on (`internal/control`); a second `session.attach` on the same connection is refused. Subscription ids still ride the wire, so multiplexing is not precluded for a later protocol version. | | |
| SQ15 | Tool events re-emit full merged state on every update, so a streaming tool grows the log quadratically. Conflate superseded full-state events in queues and the journal, or emit tool deltas? | Measure in S1a's live smoke first (bytes per session, per tool). Conflation is legal because full-state events are convergent; deltas would change the event contract. **Measured 2026-09-30 (Plan 032), left as it is by the owner:** tool events are 18.5 % of journal bytes; no conflation. | after S1a |
| SQ16 | **Resolved (Plan 027, S2).** **Answered:** a session's lifetime lock (`<HOME>/.cache/craze/locks/<crazeId>.lock`) is taken before anything is built, covering both `--continue` and the resume picker. PR 2 refuses a second `--continue` of an open session (`craze: that session is open in another craze (pid N)`); **PR 4 changes the default: the second `craze -c` attaches instead** (`craze attach --session <hostId>`, resolved through the holder's host id), unless the row is a legacy one (no craze id yet) or the spawn flags a new session would take are refused first (`internal/cli/tui.go:305-393`, `internal/cli/attach.go:406-436`). The resume picker still only shows an error row and the hint; it never itself becomes a client. | | |
