# 08 — Decisions

"owner" in the source column means the repository owner decided it in the

| SD-01 | 2026-09-19 | **The three features are built as one engine with several frontends.** Remote control, the shed lane, and the agent view share fan-out, a sequenced transcript, engine-owned asks, and idempotent commands. | Each feature alone would re-solve the same four gaps; built once, the features become transports. | `03`; craze review |
| SD-02 | 2026-09-19 | **One process per session plus a thin per-machine hub that owns no sessions.** Not a single daemon. | A daemon crash or upgrade would kill every agent; in-process native sessions would share a failure domain; a routing-only hub needs one protocol integer instead of exact version equality. | owner; prox `internal/proxyd/daemon.go` |
| SD-03 | 2026-09-19 | **The protocol is craze's own JSON-RPC 2.0 over NDJSON on one duplex stream, reusing ACP vocabulary.** Not HTTP+SSE, not ACP extended. | House style already; one connection for commands and events; maps 1:1 onto socket, stdio bridge, and WebSocket. ACP lacks attach, cursors, roster, queue, addressable asks. | owner; `05` |
| SD-04 | 2026-09-19 | **Local control is a Unix socket; authorization is same-uid (0700 dir, 0600 socket, peer-credential check). No TCP listener, token, or discovery record locally.** | Loopback TCP has no peer identity, which is why gx needs a token file, `healthz` pinning, a probe script, and a stale metadata hint. roost already works this way. | gx `docs/gx/REMOTE_API.md`; shed `epics/roost-pivot.md` |
| SD-05 | 2026-09-19 | **`craze bridge` is the stable entry point for SSH clients and resolves the dial target itself.** | Clients never learn socket paths or whether a hub exists, so the hub can arrive later without changing them. shed-mobile already pumps a Unix socket over an SSH exec for roost. | shed-mobile `lib/ssh/roost_tunnel.dart` |
| SD-06 | 2026-09-19 | **Per-session sockets first (S2); the hub later (S4) with the identical protocol.** Every session-scoped method carries `sessionId` from day one. | Ships the shed lane before the lifecycle-heavy hub exists; a per-session socket is a hub with one row. | `02` |
| SD-07 | 2026-09-19 | **craze journals every session, ACP and native, to an append-only JSONL log, rich enough to mine for errors and optimizations.** | Durable attach for ACP providers, which store nothing in craze today, and a debug and improvement corpus the owner wants. Accepts being a second source of truth beside the agent's replay. | owner; `04` |
| SD-08 | 2026-09-19 | **The journal is the UI-facing rail at the `agent.Event` layer; the harness store stays the model-facing rail, and `internal/harness` stays ignorant of the journal.** | The two-rails rule from the harness reference review; the depguard boundary is worth more than convenience. | SD-09 | 2026-09-19 | **Attach is snapshot or replay from `afterSeq`, then live events, then `synchronized`; subscribe before reading; replay bounded by bytes and rows; a slow subscriber is reset, never waited for.** | Removes the "reconnect loses or duplicates output" bug class; a phone on a bad link is the normal case. | t3code `apps/server/src/ws.ts`, `LiveStreamBudget.ts`; gx ring + `reset` |
| SD-10 | 2026-09-19 | **Asks are engine-owned resources addressable by id; first answer wins; resolutions are sequenced events; cancel is an acknowledged request.** | Two clients must agree on what is open. | SD-11 | 2026-09-19 | **Mutating commands carry a client-generated id; receipts are in memory, bounded, per host.** | "Did my prompt go through?" after a dropped link needs an idempotent resend. Persisted receipts are t3code's answer and more than a host-lifetime session needs. | t3code command receipts |
| SD-12 | 2026-09-19 | **S1–S5 are committed. S6 (`craze web` on the tailnet) and S7 (relay) are directional, decided after S1–S5 are in use; the design must not preclude them.** | If shed-mobile and desktop work well, S6 and S7 may be deferred entirely; S7's one clear benefit is reach off the tailnet, and the owner's phone is on it. | owner |
| SD-13 | 2026-09-19 | **Remote transport starts as session-tagged frames over one WebSocket. yamux is deferred until raw byte streams need per-stream flow control.** | prox's yamux streams are opaque byte pipes with no message protocol; the protocol is the work. WebSocket passes proxies and leaves the server language open. | prox `internal/proxyd/tunnel.go` |
| SD-14 | 2026-09-19 | **The first remote server is Go; the protocol is specified by JSON Schema, fixtures, and a fake host, with `shed-craze` (Rust) as the second implementation.** | Pragmatism of shared code without an implicit, Go-struct-only protocol, which is where prox ended up. | owner's stated tension; shed `fake_gx.py` |
| SD-15 | 2026-09-19 | **roost remains the status authority for tab-hosted sessions; the craze socket adds transcript and control. No pane scraping.** | shed's standing rule: one status authority per session. | shed `epics/roost-pivot.md` |
| SD-16 | 2026-09-19 | **Anything remote is gated by a capability allow-list enforced on the craze side, with a positive method list for remote clients.** | The controlled end decides what is invocable; "local minus some" routers fail open. | prox D11, `tunnel_client.go`, `hub_server.go` |
| SD-17 | 2026-09-19 | **S1 does not block harness H2, and lands before any harness phase that adds an ask channel, sub-agent event plumbing, or resume.** | H2 adds no `agent.Event` field and keeps one emit choke point; asks, child events, and replay would otherwise be built twice. | `11`; Plan 019 reply from the craze-harness session |
| SD-18 | 2026-09-19 | **The event log is per event and never coalesced; live delivery and replay use one representation. Attach has a single cutoff taken under the ordering boundary, served from an in-memory ring and, behind it, the journal.** Resolves SQ2 against its original default. | A client attaching between an emitted delta and its coalesced flush would find it in neither source; stable entry ids prevent duplicates but do not recover missing updates. Folding is the transcript model's job. | panel (Codex 1, CodeRabbit 2); `03`, `05` |
| SD-19 | 2026-09-19 | **One ordering boundary: a new leaf lock under which sequence assignment, the transcript fold, the ring append, and subscriber enqueue happen, inline in emit. No I/O and no calls into the session under it; payloads are immutable. One component, shared by every `Session` implementation including `tui.Stub`. At most one blocking lossless primary subscriber; everyone else is budgeted.** | `craze prompt` and the TUI rely on "emitted means buffered" (`drainBuffered`, `turnSettled`), which a pump goroutine breaks; `queueTx` emits while holding `emitMu`, so the boundary cannot be `emitMu`; the Stub drives every golden. Sequence numbers order events, not state, so state-carrying events must be convergent. | planning read of `prompt.go`, `live_queue.go`; panel (Codex 2, CodeRabbit 5) |
| SD-20 | 2026-09-19 | **The journal and wire use a new lossless, versioned codec for `agent.Event`. `craze prompt --json` stays a lossy projection with its own compatibility promise and gains only `seq`.** Corrects the first draft of `03` and `05`. | `eventJSON` drops ask ids, option kinds, question and plan bodies, `Replayed`, timestamps, tool input and diffs, caps output at 2 KiB, and discards bare `EventMeta`. | `internal/cli/events.go`; panel (Codex 3, CodeRabbit 3) |
| SD-21 | 2026-09-19 | **One journal file per host incarnation; no process appends to another's file. The writer is a budgeted subscriber that never blocks the engine; overflow or a write error is a recorded, published gap that invalidates replay across it.** Supersedes `04`'s "may backpressure briefly". | Torn-tail tolerance is not an append-recovery policy; a stalled regular-file write is unbounded; queue operations emit on the TUI's own update goroutine. | harness `store.go` crash semantics; panel (Codex 6, CodeRabbit 16) |
| SD-22 | 2026-09-19 | **Durable craze session id, provider session id, and host incarnation are three identities. Sequence numbers and ask ids are scoped to an incarnation; a cursor names its incarnation and a foreign one is a `reset`.** Resolves SQ5. | Counters restart with the process; a client that saw an unflushed tail would otherwise treat reused numbers as duplicates; `perm-N` ids collide across restarts. | panel (Codex 5, CodeRabbit 4) |
| SD-23 | 2026-09-19 | **Within an incarnation the ring and journal are the transcript authority. Across incarnations the provider's own replay stays the authority (ACP `session/load`; for native, the store's leaf→root walk at H7); replayed events are journaled, flagged. Restoring from earlier journals is an open question (SQ13).** Narrows SD-07's attach promise. | Restoring the journal and then applying the provider's replay duplicates history; suppressing the replay loses the state it rebuilds; cursor replays tools under different ids, so dedupe by id fails. | `live.go` `loadSession`; panel (Codex 7, CodeRabbit 4) |
| SD-24 | 2026-09-19 | **The engine owns the turn driver: prompt admission, queue removal-plus-claim, send-now arbitration, the foreign-turn wait, prompt completion with synthetic endings and rows. Clients submit commands and observe.** Extends SD-10. | `sendText`, `drainSettledTurn`, `fireStrongSend`, and `craze prompt`'s `runLoop` are drivers living in clients; `PopQueue` is only a guard. Two clients would double-drain; a headless host would never drain. | panel (Codex 4, CodeRabbit 6) |
| SD-25 | 2026-09-19 | **First *valid* answer wins, atomically; offered options are preserved verbatim including duplicate kinds; every ask ending is a sequenced terminal event. Cancel answers with an outcome against an engine turn id. Command ids are reserved in flight, payload-matched, incarnation-scoped, with an advertised retry horizon. Settings have an engine order and a confirmed, revisioned result.** Refines SD-10 and SD-11. | `AnswerPermission` removes the ask before validating; grok really offers two `allow_once` options; most ask endings emit nothing today; `Cancel` has five wire outcomes and can time out after the write; the setters call the provider outside `s.mu` and complete in any order. | `live.go`; `session.go` `OptionIDForKind`; panel (Codex 8–11, CodeRabbit 8–9) |
| SD-26 | 2026-09-19 | **Approval policy is separate from frontend presence.** A host with no client can park asks and keep them across disconnects; `craze prompt`'s auto-answering stays as an explicit policy through the same registry. | `Options.Interactive` false auto-answers questions and accepts plans, and `craze prompt` defaults to force; reusing that lifecycle for headless hosts would defeat approving from the phone. | panel (Codex 17) |
| SD-27 | 2026-09-19 | **The runtime namespace is validated, absolute, and short. Lifetime locks guard probe/unlink/bind; unlink is identity-checked; peer uid is verified on accept and on dial; the umask is set around bind. What `craze bridge` may assume under an SSH exec is specified, not inherited.** Refines SD-04 and SD-05. | `sun_path` limits; relative `CRAZE_HOME` is legal; connect failure races a bind; `MkdirAll` does not fix an existing directory; an SSH exec lacks the tab's environment and `PATH`. roost has reference implementations of each. | roost `runtime_dir.rs`, `single_instance.rs`, `socket_guard.rs`, `peer.rs`, `ssh.rs`; panel (Codex 13–14, CodeRabbit 10–11) |
| SD-28 | 2026-09-19 | **S2 defines transport close, view close, and session stop as three things, and its protocol already separates connection-level from session-level capabilities, has subscription ids, and orders the roster by its own epoch.** Refines SD-06. | Every exit path closes the session today; a hub fronts heterogeneous hosts; a crashed host cannot journal its own removal. Without these, per-session-sockets-first creates protocol rework. | panel (Codex 15–16, CodeRabbit 12) |
| SD-29 | 2026-09-19 | **The shed lane keeps the device's stable local-port pump and changes only the remote endpoint to `craze bridge`; `shed-craze` segments craze's events into append-only rows; no upsert crosses into shed's DTOs; history is a bounded page.** | Dart owns SSH and an SSH handle cannot cross FRB; `RcFeedMessage` has no entry id and the shared fold appends; `AgentLane::history` returns a page. | shed-mobile `roost_tunnel.dart`, `rust/src/api/lane.rs`; shed `lane_view.rs`, `rc.rs`; panel (Codex 12, 19; CodeRabbit 14) |
| SD-30 | 2026-09-19 | **The event stream becomes a complete record in S1b: TUI-authored rows are split into shared (engine-emitted) and client-local, and bare `EventMeta` gives way to state deltas. | SD-31 | 2026-09-19 | **SD-08's two rails are this folder's decision, not the harness's.** The harness chose pi's single tree store and dropped its own two-rail proposal (harness D-03). | SD-32 | 2026-09-19 | **The journal is fed directly and without blocking from inside the ordering boundary; it is not a droppable subscription.
