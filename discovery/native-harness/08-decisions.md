### D-40 constraint table

Reproduced from Plan 019 §3.4, re-run in C8's commit message and again after
the live smoke (C14):

| Fantasy constraint | H2 workaround | what owning the loop would give |
|---|---|---|
| no tool progress hook | `Env.Progress`, carried by the bridge's closure | nothing more: any loop needs the same func |
| a tool's Go error fails the turn | `Prepared.Run` has no error return; the bridge always returns nil | nothing more |
| tool callbacks and progress run on tool goroutines, up to five at once | one mutex-guarded per-turn state; the sink is serialized; progress is dropped rather than blocked | a single-threaded event pump |
| parallel cap of 5; "sequential" means "not with other sequential tools" | reads and searches `Parallel`; `bash`/`edit`/`write` not; a per-path lock in `edit`/`write` | real batch policy |
| unbounded wait on tools | every tool honours `ctx`; bash bounds its own waits; file tools refuse non-regular files (a FIFO read ignores `ctx`) | a per-tool deadline the loop enforces |
| error from `OnToolCall` leaks a goroutine | callbacks return nil; a test asserts it | — |
| `OnStepFinish`'s error is ignored, so a failed save would not stop further paid steps and file changes | a `StopCondition` that reports the first persistence failure | failing fast, before the next request |
| the assistant message is delivered only at step end | the step is persisted at `OnStepFinish` as one append | persisting a call before it runs, which H7's resume will want |
| `PrepareStep`'s message list applies to **one** step | the runner re-splices every drained steer on every later step | a message list the loop owns |
| calls on `length`, `error`, `content-filter`, `unknown` finishes are recorded but not run | the runner writes an error result per recorded call (D-43) | grok's salvage becomes possible |
| history is not re-read per step | not needed until compaction | compaction mid-turn |
