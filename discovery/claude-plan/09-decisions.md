# 09: Decisions

Append-only. A reversal is a new row naming the old one.

| id | date | decision | why | evidence |
|---|---|---|---|---|
| CLD-01 | 2026-11-11 | **t3code's model is the accepted model for craze's Claude provider.** craze drives the user's own signed-in `claude` through the Agent SDK's ecosystem (an SDK-based adapter, or the same protocol), runs no claude.ai login of its own, and holds no Claude credential. A plan built on this needs no prior written confirmation from Anthropic. Resolves CLQ-1. | The owner's call. t3code works this way, is widely used and well known, and is taken as within Anthropic's terms. Route A (`claude-agent-acp`, which runs on the Agent SDK as t3code does) and route B (the same `claude` binary, without the SDK) both sit inside that model. craze still reads nothing under `~/.claude`: the plan's rate-limit state arrives on the wire (`usage_update._meta["_claude/rateLimit"]`, [08](08-cl0-results.md)), so the one thing t3code reads the credential file for is not needed. | [02](02-policy-and-billing.md), [03](03-reference-implementations.md) |
| CLD-02 | 2026-11-11 | **Overage is an error.** A turn that would draw "extra usage" instead of plan limits ends with a typed craze error, not assistant text. The signals: the rate-limit object on a turn's `usage_update` (`_meta["_claude/rateLimit"].isUsingOverage: true`), or an API billing error such as "Third-party apps now draw from your extra usage". On the first signal mid-turn, craze cancels the turn (`session/cancel`) and reports why. | The owner's call. Plan limits are the whole reason for the provider; spending real money silently is worse than failing. CL0 showed the signal is on the wire. | [08](08-cl0-results.md) |
| CLD-03 | 2026-11-11 | **A listed provider, never hidden.** Like the other ACP providers, it is offered when its binaries resolve and shown as unavailable when they do not. It needs both `claude-agent-acp` (or its standalone release) and the user's `claude`. Implemented with `optional: true` plus a second binary check. | The owner's call. This reverses the earlier sketch's "hidden first" CL1. | — |
| CLD-04 | 2026-11-11 | **Claude Code's background work gets its own design section in the build plan.** A turn Claude Code starts on its own (a background Bash or Agent finishing) is a foreign turn, handled as native's wake is (`ForeignTurn()`). The host's idle watcher, the unattended limit and `--exit-after-turn` count Claude's open background tasks and running children as in flight, from the adapter's `subagent_update` and `async_task_*` updates. Cancel's documentation states that background commands survive a cancel. | The owner took the review's recommendation ([10](10-review.md) item 3): this is where real bugs would be, more than in the dialect. | [08](08-cl0-results.md) (background wake) |
| CLD-05 | 2026-11-11 | **Inherit the user's Claude Code setup as it is, and assume a Claude session does not call craze.** Hooks, plugins, MCP servers, skills, `settings.json` and its permission rules all apply, unfiltered; craze strips nothing and adds no recursion guard. Revisit if delegation back into craze becomes a real case. | The owner's call: nothing fancy for now. | [08](08-cl0-results.md) (hooks, plugins and craze agents seen in the probe) |
| CLD-06 | 2026-11-11 | **Route A (ACP through `claude-agent-acp`) is the plan; route B (Go stream-json) is the pivot.** Pivot if the adapter's churn, its Node dependency, or a gap A cannot close starts to hurt. Route B's protocol notes ([03](03-reference-implementations.md), [08](08-cl0-results.md) probe 1) and its probe script stay in this folder for that. | The owner's call. | [04](04-options-and-design.md) |
